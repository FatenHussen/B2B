# تطبيق المندوب — العروض، إنهاء التسليم، المحفظة

ملف تنفيذ لـ Flutter. يغطي ثلاث شاشات فقط: إضافة عرض إلى طلب، إنهاء التسليم، والمحفظة (استلام دفعة، تسليم دفعة، الذمم، السحوبات).

العقد الكامل يبقى [`flutter-rep.md`](flutter-rep.md). هذا الملف يحدّد ماذا يستدعي التطبيق بعد آخر تعديل على الخادم.

الأساس `https://<host>/api/v1`. الحارس `Authorization: Bearer`. لا ترسل `X-Channel-Id`.

كل كتابة تحمل `X-Idempotency-Key` جديداً عند ضغط التأكيد، ويُعاد نفس المفتاح عند إعادة المحاولة. المبالغ أعداد صحيحة بالليرة السورية كما هي — لا تقسم على 100.

حساب تجربة: `+963932000001` (عمر الشامي). رمز OTP المحلي النص `"0000"`.

## 1. إضافة عرض إلى الطلب

العرض لا يُرسل كسطر مستقل. بطاقة العرض تعطي `components[]`، وكل مكوّن يصير سطراً في المسودّة المحلية، ثم يُرسل كمنتج عادي. الخادم يطبّق الخصم أو الهدية عند التسعير.

### 1.1 جلب العروض

بعد اختيار المحل:

`GET /app/offers?filter[zone_id]={zone_id}&filter[activity_type_id]={activity_type_id}&page=1`

`zone_id` منطقة المحل. `activity_type_id` نشاط المحل إن وُجد، وإلا نشاط المندوب من الجلسة. الفلتران اختياريان.

قائمة فارغة = أخفِ السلايدر. هذا ليس خطأ.

```json
{
  "data": [{
    "id": 1,
    "image": null,
    "name": "خصم 10% على زيت الدرة 1 ل",
    "company": null,
    "rating": 0,
    "components": [{ "product_id": 880, "qty": 1 }],
    "price_before": 120000,
    "discount": 12000,
    "price_after": 108000,
    "ends_at": "2026-11-21T23:59:59+03:00",
    "days_left": 20,
    "remaining_qty": 2000,
    "sold_count": 0
  }]
}
```

البطاقة: `name` و `price_after`. الصورة `image`، وإن كانت `null` فحرف من الاسم. `company` يبقى `null`.

النقر على البطاقة: `GET /app/offers/{id}` يعيد نفس البطاقة بالإضافة إلى `images` و `long_description` و `icons`.

عروض جاهزة للتجربة على كل قناة فيها منتجات:

| الاسم | ماذا تضيف للمسودّة |
|---|---|
| خصم 10% على زيت الدرة 1 ل | مكوّن الزيت بكمية المكوّن |
| اشترِ 10 سكر واحصل على 1 مجاناً | السكر بكمية 10 على الأقل |
| باقة الإفطار | الجبنة + اللبنة + الحليب. تظهر لمناطق المزة والمالكي وكفرسوسة والميدان |
| هدية شيبس مع كل كرتونة كولا | الكولا بكمية 24. لنشاط سوبر ماركت أو بقالة |
| خصم 25,000 ل.س على فواتير فوق 500,000 | بلا مكوّنات. ينطبق إن بلغ مجموع السلة الحد |

### 1.2 من البطاقة إلى المسودّة

زر الإضافة على البطاقة لا ينادي الخادم. لكل عنصر في `components[]` أضف سطراً محلياً:

```text
product_id = component.product_id
qty        = component.qty
variant_id = null
```

اسم السطر وصورة المنتج من كاش `GET /app/rep/products` بنفس `product_id`. إن لم يكن المنتج في الكاش، اجلب تفاصيله قبل رسم السطر.

المسودّة محلية. الإنقاص والحذف هنا فقط. الشريط العائم «قائمة المنتجات والعروض المختارة» يظهر عندما المسودّة غير فارغة.

### 1.3 من المسودّة إلى السلة

نداء واحد لكل سطر، ومفتاح تكرار جديد لكل نداء:

`POST /app/rep/cart/lines`

```json
{
  "retailer_id": 481,
  "product_id": 880,
  "qty": 1
}
```

`variant_id` يُرسل فقط إن اختار المستخدم متغيراً. لا ترسل `offer_id`.

الرد هو السلة كاملة. بعد نجاح كل الأسطر امسح المسودّة. الخادم يجمع الكمية على سطر موجود لنفس المنتج، ولا يوجد حذف من السلة في هذه الخطوة.

إن ظهر خصم أو سطر هدية بكمية وسعر 0، هذا أثر العرض. لا تحسبه مرة ثانية على الجهاز.

### 1.4 إرسال الطلب

إرسال الطلب من السلة ليس إنهاء التسليم، ولا يمر على العهدة.

`POST /app/rep/cart/sections/{retailer_id}/submit`

```json
{ "note": "توصيل صباحي", "discount_percent": 0 }
```

```json
{
  "data": {
    "sub_order": {
      "id": 9001,
      "sub_order_no": "SO-9001",
      "invoice_no": null,
      "status": "pending",
      "shop": "بقالية النور",
      "total": 108000
    }
  }
}
```

شاشة النجاح: الرقم `sub_order_no`، الحالة «بانتظار الموافقة» ما دام `status` = `pending`، والمبلغ `total`.

| خطأ | ماذا تعرض |
|---|---|
| 403 `discount_cap_exceeded` | الخصم أعلى من سقف الجلسة |
| 422 | السلة فارغة لهذا المحل |
| 404 | المحل أو المنتج غير ظاهر لهذا المندوب |

## 2. إنهاء التسليم

الخطأ الذي كان يظهر عند الإنهاء:

```json
{
  "error": {
    "code": "illegal_transition",
    "message": "Handover is not confirmed."
  }
}
```

معناه: استدعيت `POST /app/rep/deliveries/{id}/complete` والطلب لم يصبح `on_the_way` بعد. أكّد استلام العهدة من المستودع أولاً. لا تعامله كفشل في إرسال سلة جديدة.

طلب حالته `on_the_way` أو `delivered` يُنهى. طلبات التجربة التي كانت عالقة على هذا الخطأ صارت `on_the_way` ومعها عهدة مؤكدة. اسحب قائمة التسليم ثم أعد الإنهاء.

### 2.1 متى يظهر زر الإنهاء

`GET /app/rep/deliveries`

البطاقة الخضراء (`border_color` = `green` أو `status` = `on_the_way`) تُنهى مباشرة.

البطاقة الزرقاء (`accepted`) لا تُنهى. افتح استلام المستودع، أكّد العهدة، ثم ارجع وأنهِ.

### 2.2 تأكيد العهدة

`GET /app/rep/warehouse-receipts`

لكل صف `handover_id` و `parties.rep`. إن كان `pending`:

`POST /app/rep/warehouse-receipts/{handover_id}/confirm`

```json
{ "temp_code": "4821" }
```

`temp_code` أربع خانات يعرضها المستودع. النجاح:

```json
{
  "data": {
    "status": "on_the_way",
    "parties": { "rep": "confirmed", "warehouse": "confirmed" }
  }
}
```

بعد هذا الرد حدّث قائمة التسليم. البطاقة صارت قابلة للإنهاء.

| خطأ | ماذا تعرض |
|---|---|
| 422 | الرمز غير صحيح |
| 409 `illegal_transition` | العهدة ليست لهذا المندوب |

### 2.3 الإنهاء

`POST /app/rep/deliveries/{id}/complete`

```json
{
  "lines": [{ "line_id": 1, "qty_delivered": 4, "action": "accept" }],
  "delivered_at": "2026-11-01T12:05:00+03:00"
}
```

كل الحقول اختيارية. بلا `lines` يُحتسب المتوقع.

```json
{
  "data": {
    "shop": "بقالية النور",
    "delivered_at": "2026-11-01T12:05:00+03:00",
    "invoice": { "no": "INV-501", "total": 480000 },
    "receipt_no": "RCPT-10041",
    "ask_payment": true
  }
}
```

شاشة «تم تسليم الطلب»: `shop`، `delivered_at`، والمبلغ `invoice.total`. جملة ثابتة: «التسليم لا يعني التحصيل».

`ask_payment: true` يفتح استلام الدفعة بهذه القيم، ولا يُستدعى `POST /app/receipts/reserve`:

- `receipt_no` من هذا الرد
- رقم الفاتورة `invoice.no`
- المبلغ المقترح `invoice.total`

إعادة الإنهاء لنفس الطلب تعيد نفس الفاتورة ونفس الوصل. عاملها كنجاح.

| `error.code` | النص في الحوار |
|---|---|
| `illegal_transition` والرسالة عن العهدة | «أكّد استلام العهدة من المستودع أولاً» ثم افتح شاشة المستودع |
| `not_found` | الطلب ليس لهذا المندوب |

## 3. المحفظة

المسار الأساسي `GET /app/rep/wallet`. بعد أي تحصيل أو تسليم أعد هذا النداء، وأعد `GET /app/rep/home` حتى يتحرك عدّاد اليوم.

بيانات التجربة الحالية لكل مندوب، بالليرة:

| الحقل | القيمة |
|---|---|
| `net_balance` | 100000 |
| `stats.collected_total` | 150000 |
| `stats.handed_over` | 50000 |
| سجل السحوبات | صف واحد بمبلغ 50000، رقمه يبدأ بـ `OP-D` |
| الذمم | فواتير مفتوحة، إحداها `paid > 0` |

اسحب للتحديث إن ظهرت المحفظة أصفاراً من كاش قديم.

### 3.1 لوحة المحفظة

`GET /app/rep/wallet`

الثابت في بيانات التجربة هو `net_balance` و `collected_total` و `handed_over`. بقية `stats` مجموع فواتير هذا المندوب، فتختلف من حساب لآخر. `today` أصفار إن لم يحصّل اليوم.

```json
{
  "data": {
    "net_balance": 100000,
    "stats": {
      "invoices_delivered": 3,
      "invoiced_total": 0,
      "collected_total": 150000,
      "handed_over": 50000,
      "receivables": 0
    },
    "today": {
      "invoices": 0,
      "invoiced_total": 0,
      "collected": 0,
      "receivables": 0
    }
  }
}
```

`invoiced_total` و `receivables` في المثال أعلاه مكانان للقيم الراجعة. لا تثبّت الاختبار عليهما.

| مكان على الشاشة | الحقل |
|---|---|
| الصافي | `net_balance` |
| إجمالي الفواتير | `stats.invoiced_total` |
| المحصّل | `stats.collected_total` |
| المسلّم للمحاسب | `stats.handed_over` |
| الذمم | `stats.receivables` — النقر يفتح §3.4 |
| السحوبات | النقر يفتح §3.5 |

`today` هو يوم دمشق فقط. إن اختار المستخدم يوماً آخر اعرض «أرقام اليوم من الخادم» ولا تخترع تفصيلاً.

### 3.2 استلام دفعة

من الرئيسية، أو من «استلم دفعة الآن» بعد الإنهاء.

ترتيب الحقول:

1. رقم الوصل، للقراءة فقط.
2. التاريخ والوقت واسم المندوب من الجلسة.
3. اسم المحل.
4. رقم الفاتورة، اختياري.
5. مبلغ الدفعة.
6. تأكيد الاستلام.

**بعد إنهاء التسليم:** الوصل والفاتورة والمبلغ المقترح من رد `complete`. لا تحجز وصلاً ثانياً.

**من الرئيسية:** أولاً

`POST /app/receipts/reserve` بجسم `{}`

```json
{ "data": { "receipt_no": "RCPT-10042" } }
```

المحل من `GET /app/rep/customers`. فواتير هذا المحل من `GET /app/rep/receivables` ثم صف `by_shop` الذي `retailer_id` فيه يساوي المحل. المبلغ المقترح = `remaining` للفاتورة المختارة.

ثم:

`POST /app/rep/payments`

```json
{
  "receipt_no": "RCPT-10042",
  "retailer_id": 5,
  "invoice_no": "INV-120",
  "amount": 50000,
  "paid_at": "2026-11-01T14:08:00+03:00",
  "client_op_id": "op_rep_pay_10042"
}
```

`invoice_no` يُحذف من الجسم إن تركه المستخدم فارغاً. الخادم يخصم من أقدم فاتورة مفتوحة لهذا المحل وهذا المندوب، والرد يسمّيها.

`amount` عدد ≥ 1. `client_op_id` حتى 80 حرفاً، يُحفظ مع مفتاح التكرار حتى النجاح. `paid_at` وقت الجهاز بتوقيت دمشق.

```json
{
  "data": {
    "payment": { "id": 301 },
    "amount": 50000,
    "receipt_no": "RCPT-10042",
    "paid_at": "2026-11-01T14:08:00+03:00",
    "shop": "بقالية النور",
    "invoice_no": "INV-120",
    "invoice_remaining": 0,
    "wallet_balance": 150000,
    "retailer_receivable": 0
  }
}
```

إيصال «تم استلام المبلغ» من هذا الجسم: `shop`، `amount`، `invoice_no`، `invoice_remaining`، `wallet_balance`، `paid_at`. الرصيد الجديد هو `wallet_balance`، لا تجمعه محلياً على الرقم القديم.

| خطأ | ماذا تعرض |
|---|---|
| 404 | لا فاتورة مفتوحة لهذا المحل، أو المحل ليس لك |
| 409 `duplicate_receipt_no` | الوصل مستخدم. من الرئيسية احجز وصلاً جديداً. بعد التسليم أعد نفس `receipt_no` |
| 422 على `receipt_no` | الوصل غير محجوز أو انتهت ساعاته الأربع والعشرون |
| 403 `cash_cap_exceeded` | المبلغ يتجاوز سقف النقد في الجلسة |
| 409 `idempotency_key_conflict` | المفتاح تكرر بجسم مختلف. مفتاح جديد فقط إن غيّر المستخدم البيانات |

### 3.3 تسليم دفعة للمحاسب

يُفتح من المحفظة. امنع الزر محلياً إن كان المبلغ أكبر من `net_balance` أو أصغر من 1.

`POST /app/rep/wallet/withdrawals`

```json
{
  "amount": 40000,
  "operation_no": "OP-9001",
  "operated_at": "2026-11-01T16:00:00+03:00"
}
```

`operation_no` يكتبه المحاسب، حتى 32 حرفاً، وفريد على القناة. لا تولّده على الجهاز إلا كاقتراح يقدر المستخدم أن يبدله. التجربة فيها رقم يبدأ بـ `OP-D` — لا تعِد استخدامه.

```json
{
  "data": {
    "amount": 40000,
    "operated_at": "2026-11-01T16:00:00+03:00",
    "remaining_balance": 60000
  }
}
```

شاشة «تم تسليم المبلغ»: `amount` المسلّم، `remaining_balance` الباقي، `operated_at`. «افتح كشف التسليمات» يفتح §3.5. لا PDF من الخادم.

إن أعاد الخادم 422 على `amount` فالنص: المبلغ أكبر من رصيد المحفظة. حدّث `GET /app/rep/wallet` ثم أعد المحاولة.

### 3.4 الذمم

`GET /app/rep/receivables`

```json
{
  "data": {
    "total": 750000,
    "by_shop": [{
      "retailer_id": 5,
      "shop": "بقالية النور",
      "zone": "المزة",
      "channel": "شركة النور",
      "total": 400000,
      "invoices": [{
        "no": "INV-120",
        "total": 550000,
        "paid": 150000,
        "remaining": 400000,
        "created_at": "2026-10-30T11:00:00+03:00"
      }]
    }]
  }
}
```

«إجمالي الذمم» = `total`. داخل المحل، شارة «محصّل جزئياً» عندما `paid > 0` و `remaining > 0`. تاريخ الفاتورة `created_at`.

النقر على فاتورة يفتح استلام الدفعة: `retailer_id` من صف المحل، `invoice_no` = `no`، والمبلغ المقترح `remaining`. هذا المسار من الذمم يحتاج حجز وصل (`reserve`) لأنه ليس آتياً من `complete`.

قائمة فارغة: «لا ذمم مفتوحة.»

### 3.5 السحوبات

`GET /app/rep/wallet/withdrawals?date_from=2026-11-01&date_to=2026-11-01`

التاريخان اختياريان. بلاهما ترجع كل التسليمات.

```json
{
  "data": {
    "rows": [{
      "operation_no": "OP-D1-9",
      "amount": 50000,
      "operated_at": "2026-11-01"
    }],
    "total": 50000
  }
}
```

`operated_at` يوم، ليس ساعة. `total` مجموع الصفوف المعروضة. PDF الكشف يُرسم على الجهاز من `rows` و `total`. لا مسار ملف على الخادم.

## 4. ترتيب التجربة

1. سجّل دخول عمر، واسحب الرئيسية.
2. تسجيل طلب: منطقة ثم محل، ثم سلايدر العروض. أضف «خصم الزيت» إلى المسودّة، ثم إلى السلة، ثم أرسل. الحالة ترجع `pending`. هذا ليس شاشة التسليم.
3. قائمة التسليم: بطاقة `on_the_way` → إنهاء. احفظ `receipt_no` و `invoice.no`.
4. «استلم دفعة الآن» بنفس الوصل. بعد النجاح `wallet_balance` أكبر من 100000.
5. المحفظة: الصافي هو `net_balance`. الذمم تعرض الفواتير المفتوحة. السحوبات تعرض صف `OP-D`.
6. تسليم دفعة بمبلغ ≤ الصافي ورقم عملية جديد لم يُستخدم.
