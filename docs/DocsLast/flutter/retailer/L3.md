---

## Cart — `FE-RT-CART` (SP-09)

| Method | Path | EP |
|---|---|---|
| GET | `/app/retailer/cart` | EP-RT-020 |
| POST | `/app/retailer/cart/lines` | EP-RT-021 |
| PATCH | `/app/retailer/cart/lines/{id}` | EP-RT-022 |
| DELETE | `/app/retailer/cart/lines/{id}` | EP-RT-023 |
| PATCH | `/app/retailer/cart/sections/{ref}` | EP-RT-024 |
| POST | `/app/retailer/cart/submit` | EP-RT-025 |

Every mutation returns the **full cart**. Sections use `supply_channel_ref` (opaque). **Do not** bind a company name on the cart. After submit, order list keeps `supply_channel: null` until the channel **confirms**.

| Rule | UI |
|---|---|
| BR-08 | Deleting one offer line removes **all** lines of that offer — confirm copy |
| BR-20 | Qty drop that breaks an offer → show `removed_offers[]` |
| Offline submit | Always accepted; if totals changed show `repricing_diff`. Persist `client_created_at` |
| Online + dead offer | 409 `offer_no_longer_valid` |
| Credit | 423 `credit_limit_exceeded` — stop |
| Submit | One `WriteIntent` + optional `client_op_id` for the offline outbox |

Primary CTA on product detail becomes **Add to cart** (L2 favorite stays).

## Orders — `FE-RT-ORDERS` (SP-09)

`{id}` in this app is the **sub-order** id.

| Method | Path | EP |
|---|---|---|
| GET | `/app/retailer/orders` | EP-RT-030 |
| GET | `/app/retailer/orders/{id}` | EP-RT-031 |
| POST | `.../cancel` | EP-RT-032 pending only → else 409 |
| POST | `.../reorder` | EP-RT-033 rebuilds cart at **today’s** prices |
| GET | `.../tracking` | EP-RT-034 |

`rep` and live location only when status is `on_the_way` (BR-03). `eta_minutes` may be null until SP-12. `invoice` null until delivery completes.

After **confirm** (channel), the list **may** show channel name (REQ-IN-06 complete for that order).

---

## Receive + returns + rating — `FE-RT-RECV` (SP-12)

Same line objects as the rep (REQ-IN-05). First confirm wins; second is idempotent.

| Method | Path | EP |
|---|---|---|
| GET | `/app/retailer/receipts/{subOrderId}` | EP-RT-040 |
| PATCH | receipt lines | EP-RT-041 |
| POST | confirm receive | EP-RT-042 |
| GET/POST | `/app/retailer/return-requests` | EP-RT-043/044 |
| POST | rate rep | EP-RT-045 after that delivery only |

Photos on returns = media ids. Invoice number `INV-*` appears when delivery/receive completes.

---

## Out of scope (L4)

`POST /app/retailer/payments`, statement, debts, inbox, loyalty wallet, sync pull.

## Done

1. Two-channel cart → submit creates two sub-orders; cart sections never show company names.  
2. Cancel after confirm → 409.  
3. Tracking hides the rep until `on_the_way`.  
4. Receive PATCH changes the total the shop sees.  
5. Reorder fills the cart; prices are today’s, not yesterday’s snapshot.
