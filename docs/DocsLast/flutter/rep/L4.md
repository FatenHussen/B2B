# Rep — Layer 4 (collect, wallet, sync)

| | |
|---|---|
| Backend | SP-13, SP-14 (sync + inbox). Loyalty is channel-configured; session may show rep points |

---

## Collect — `FE-RP-PAY` (SP-13)

1. `POST /app/receipts/reserve` · EP-CM-050 → `receipt_no` (`RCPT-*`). TTL ~24h.  
2. `POST /app/rep/payments` · EP-RP-060 with that number. Without reserve → 422.  
3. Repeat same number → one payment row (duplicate). Different amount → 409.

`GET /app/rep/receivables` · EP-RP-064.  
Wallet: `GET /app/rep/wallet` · EP-RP-061. Withdraw: EP-RP-062/063 with unique `operation_no` (idempotent across sync).

Never invent `wallet_matched` cash UI — bind server fields only.

---

## Sync + inbox — `FE-RP-SYNC`

Same pull/push as retailer. Extra scopes: `rep_catalog`, `customers`, `assignments`, `deliveries`, `wallet`. Push types include `payment`, `delivery.*`, `add-shop`. Do not push prices.

Inbox: same `/app/notifications*` as retailer.

---

## Out of scope

Channel settle screen, platform broadcast composer.

## Done

1. Reserve → collect → retailer records same `receipt_no` → one payment.  
2. Withdraw retry with same `operation_no` does not settle twice.  
3. Catalog push from the client is rejected.
